# プロダクト要求定義書 (Product Requirements Document)

> **ステータス**: 承認済み(2026-10-24)。同日、2回のレビューの高優先度の指摘を反映(設計判断の記録 #9〜#13)。機能設計書のレビューを受けてF1〜F3を変更(#19・#20。2026-10-25承認)
> 前提: 一般公開するWebアプリ。PCとスマートフォンの両方で利用する。
> 「(仮説)」と書かれた箇所は、公開後のデータで見直す前提の仮置きです。

## プロダクト概要

### 名称
**S+7メーカー** - 日本語WordNetで遊ぶウリポ式テキスト変換器

### プロダクトコンセプト
- **原典に忠実なS+7**: 日本語の文章中の名詞を、辞書の五十音順で7つ後ろの名詞に置き換える
- **概念版S+7**: 日本語WordNetの概念ツリーを辿ることで、「綴りの近さ」ではなく「意味のつながり」でずらす独自の派生ルールを提供する
- **すぐ遊べる**: 登録・ログイン不要。文章を貼り付けてボタンを押すだけで結果が出る

### プロダクトビジョン
ウリポの言語遊戯S+7を、日本語で誰でも手軽に試せるようにする。
五十音順という「偶然」に任せた置換と、概念ツリーという「意味」に沿った置換を同じ文章で比べることで、
言葉の並びが生む意外性と、意味のずれが生む詩情の両方を楽しめる道具を目指す。
置換の過程(どの語がどの経路で何に変わったか)を見せ、制約による創作の面白さを伝える。

### 目的
- 日本語の文章に対してS+7を自動で適用できるようにする
- 日本語WordNetの概念構造を使った新しい派生ルール(概念版S+7)を提供する
- 置換の過程を可視化し、結果の意外性を「なぜそうなったか」まで楽しめるようにする

## ターゲットユーザー

### プライマリーペルソナ: 佐藤 葵(34歳、会社員・趣味で詩や短編を書く)(仮説)
- ウリポやレーモン・クノー『文体練習』が好きで、制約を使った創作に関心がある
- 日本語でS+7を試したいが、辞書を手でめくって名詞を数えるのは手間がかかりすぎる
- 期待する解決策: 自作の文章や名作の一節を貼るだけで、すぐ変換結果が見られる
- 典型的な使い方: 夜にPCで15〜30分ほど、同じ文章をルールを変えながら何度も変換し、気に入った結果をコピーしてSNSや創作メモに貼る

### セカンダリーペルソナ: 国語・文芸創作の授業を担当する教員(仮説)
- 言葉遊びを通じて品詞や語彙の構造(上位語・下位語)を教えたい
- 授業中にプロジェクターで、その場で変換して見せたい

### サードペルソナ: 言葉遊びのボットや作品を作る開発者(仮説)
- SNSボット、ジェネラティブ詩の作品、他のWebサービスにS+7を組み込みたい
- 期待する解決策: 文章を送るとS+7の結果がJSONで返ってくるAPI
- 日本語WordNetや形態素解析の環境を自分で用意したくない

## 成功指標(KPI)

一般公開を前提とした目標値です(仮説)。公開から1ヶ月後に実績を見て見直します。

KPIの「変換」は、特に断らない限り**成功した変換**を指す(失敗した変換は下の「変換エラー率」で見る)。

### プライマリーKPI
- 画面からの変換実行数: 公開後3ヶ月で、成功した変換が累計5,000回(Web APIからの呼び出しは含めない)
- 1ページ表示あたりの変換回数: 成功した変換を1回以上行ったページ表示のうち、成功した変換の回数の平均が3回以上(ルールやNを変えて試していることの指標)

### セカンダリーKPI
- 概念版S+7の利用比率: 画面からの成功した変換のうち、概念版が30%以上(独自ルールが価値を持っているかの指標)
- 結果のコピー率: 画面からの成功した変換のうち、20%以上で結果がコピーされる
- Web APIの利用: 公開から3ヶ月目の1ヶ月間に、Web画面以外からの変換APIの成功した呼び出しが1,000回以上(目安。下記「測定方法」の限界を参照)

### 品質指標(目標値ではなく監視用)
- 置換率: 画面からの成功した変換で、`置き換えた名詞の数 ÷ 置換対象の名詞の数` を全変換で合計して求めた割合。「置き換えた名詞」は状態が「置き換えた」「階層を上がってから置き換えた」のもの。「置換対象の名詞」には、利用者が除外を指定した名詞(F7)を含めない
- 変換エラー率: 画面からの変換(成功・失敗の合計)のうち、失敗した割合(利用制限、起動中、想定外のエラーの内訳つき)
- **辞書の品質の基準**: 著作権の切れた作品から選んだ標準の文章3本(スナップショットテストと同じもの)で、両モードの置換率を測る。最初に測った値を基準として記録し、以降、置換率を5ポイント以上下げる変更(辞書・照合規則・除外リストの変更など)は、理由を説明してから行う。基準値はビルドの報告とともにリポジトリに残す

### 測定方法
- 入力した文章の中身は記録しない。画面は次の匿名のイベントだけを送る

| イベント | 送るタイミング | 項目 |
|----------|----------------|------|
| `page_view` | 変換画面を開いたとき | ページ表示ID |
| `transform` | 変換が終わったとき(成功・失敗とも) | ページ表示ID、変換ID、モード、N、文字数の区分、成否(失敗ならエラーコード)、置換対象の名詞の数、そのうち除外を指定した名詞の数、置き換えた数(置換率は「置き換えた数 ÷ (名詞の数 − 除外の数)」で求める) |
| `copy` | 結果をコピーしたとき | ページ表示ID、コピーした結果の変換ID |

- **ページ表示ID**: ページを開くたびに画面のメモリ上で作るランダムな値。Cookieや端末の保存領域に残さないため、同じ人の別の日の訪問は結び付かない。KPIの「訪問」はこのページ表示の単位で数える
- **変換ID**: ページ表示の中で変換ごとに振る通し番号。コピーがどの変換の結果かを結び付ける
- **Web画面以外からのAPI呼び出し**: サーバーが変換APIの呼び出しを数え、画面からの呼び出し(画面だけが付ける目印のヘッダーがあるもの)を差し引く
- **測定の限界**: イベントの送信とヘッダーは偽装できるため、KPIは傾向を見る目安として扱う。1つの送信元からの大量の呼び出しで数値が膨らむことは許容し、厳密な計測(認証など)はMVPでは行わない
- **集計の仕組み**: サーバーはイベントとAPIの呼び出しを、決まった形式のログ(JSON)として出力するところまでを受け持つ。ログを集めてKPIを集計する仕組みは、ホスティング先の決定時に、そのホスティング先のログ基盤に合わせて決める(候補のCloud Runなら、Cloud Loggingで集計する)。公開までに集計の仕組みを用意する

## 機能要件

### コア機能(MVP)

#### F1. テキスト入力と名詞抽出

**ユーザーストーリー**:
創作者として、手元の文章をそのまま使うために、日本語の文章を貼り付けて名詞を自動で見つけてほしい

**受け入れ条件**:
- [ ] 最大50,000文字(400字詰め原稿用紙で約125枚。短編小説1本が収まる分量)の日本語テキストを入力できる
- [ ] 入力欄に現在の文字数と上限を表示し、上限を超えた場合は変換ボタンを押せなくして理由を表示する
- [ ] 形態素解析で名詞(普通名詞)を抽出する。固有名詞・代名詞・数詞・形式名詞(「こと」「もの」など)は置換対象にしない
- [ ] 連続する名詞(複合名詞)は、つなげた語が辞書にあれば1語として扱い、無ければ個々の名詞として扱う(最長一致。例: 「図書館司書」→辞書に無ければ「図書館」「司書」)。接尾辞・接頭辞・数詞・固有名詞を含む語も、つなげた語が辞書にあれば1語として扱う(例: 「科学者」「三角形」)。単独の固有名詞・数詞・接尾辞は置換対象にしない
- [ ] 名詞以外の文字(助詞、句読点、改行、記号)は元の文章のまま保持する

**優先度**: P0(必須)

#### F2. 五十音順S+7

**ユーザーストーリー**:
ウリポ愛好家として、原典どおりのS+7を日本語で試すために、各名詞を五十音順で7つ後ろの名詞に置き換えてほしい

**受け入れ条件**:
- [ ] 日本語WordNetに収録された名詞を読み(ひらがな)で五十音順に並べた見出し語リストを辞書として使う
- [ ] 読みは形態素解析辞書から補う。表記がかな(ひらがな・カタカナ・長音符・中黒)だけの見出し語は、表記をそのまま読みにする(中黒は除く)。それでも読みが決まらない見出し語は五十音順のリストに含めない(計測では、日本語の名詞の見出し語の約97.5%に読みが付く。architecture.md「設計前の検証結果」)
- [ ] 読みが決まらない見出し語が入力文にある場合は置き換えずに残し、「辞書に無い語」とは別に「読みが分からない語」として見分けられるようにする(この語も概念版S+7では置き換える)
- [ ] 並び順は国語辞典の慣例に従う(清音→濁音→半濁音の順、長音「ー」は直前の母音として扱う。詳細は機能設計書で定義)
- [ ] 同じ読みの見出し語が複数ある場合は、表記の文字コード順で並べる
- [ ] 各名詞を、リスト上で7つ後ろの名詞に置き換える
- [ ] リストの末尾を超えた場合は先頭に戻る(循環する)
- [ ] 辞書に載っていない名詞は置き換えずに残し、「辞書に無い語」として見分けられるようにする
- [ ] 同じ入力・同じ設定なら、何度実行しても同じ結果になる
- [ ] **置換先から除外する語のリスト**(差別語・卑語など、一般公開の出力にふさわしくない語)に載っている語は、五十音順リストに含めない。したがって置換後の語として出ることは無い(下記「置換先から除外する語」)

**優先度**: P0(必須)

#### F3. 概念版S+7

**ユーザーストーリー**:
創作者として、意味のつながりを保ったまま不思議にずれた文章を作るために、概念ツリー上で7つ先の概念の名詞に置き換えてほしい

**受け入れ条件**:
- [ ] **兄弟概念方式**で置き換える: 名詞の概念(synset)と同じ上位語を持つ概念(兄弟概念)を決まった順に並べ、7つ先の概念の名詞に置き換える
- [ ] 兄弟概念は、日本語の見出し語を1つ以上持つものだけを対象にする
- [ ] 兄弟概念の並び順は、各概念の代表語の読みの五十音順とする(F2と同じ並び順ルール)。読みが決まらない代表語の概念は、読みのある概念の後ろに表記の文字コード順で並べる
- [ ] 兄弟概念のリストの末尾を超えた場合は先頭に戻る(循環する)
- [ ] 兄弟概念が自分しかない場合は、1つ上の上位語の階層に上がって同じ処理を行う。最上位まで上がっても兄弟が無い場合は置き換えない。階層を上がったことは画面上で分かる
- [ ] 上位語が複数ある概念は、決まったルールで1つを選ぶ(概念IDの小さい方)
- [ ] 置換先の概念に日本語の見出し語が複数ある場合は、読みの五十音順で先頭の語を使う。読みの決まる語が無い場合は、表記の文字コード順で先頭の語を使う
- [ ] 読みが決まらない見出し語(F2で五十音順のリストに入らない語)も、置換元・置換先の両方で使う。概念版は読みを使わないため
- [ ] 1つの名詞が複数の概念(語義)を持つ場合は、下記「語義の選び方」のルールで1つを選ぶ
- [ ] 同じ入力・同じ設定なら、何度実行しても同じ結果になる
- [ ] 置換先から除外する語のリストに載っている語は、概念の代表語にしない。除外した結果、日本語の見出し語が1つも残らない概念は、兄弟概念の対象から外す(F2と同じリストを使う)

**置換先から除外する語**(F2・F3共通):
- 対象: 差別語、卑語、性的な語など、一般公開のサービスの出力としてふさわしくない語
- リストは変換用辞書のビルド時に適用する。実行時に結果を書き換えないため、決定性は保たれる
- リストを変えると変換結果が変わるため、辞書のバージョンを上げて行う
- リストに載っている語が入力文にある場合は、辞書に無い語と同じく置き換えずに残す
- リストで全てを防ぐことはできないため、「このアプリについて」に、辞書から機械的に選んだ語であり意図しない語が出る場合があること、気付いた語の報告先を書く

**除外リストの公開前の完了条件**(公開の前提条件。満たすまで一般公開しない):
- [ ] 初版のリストを次の手順で作り、`data/excluded-lemmas.txt` に入れる
  1. 再配布・改変が認められたライセンスの、日本語の不適切語の既存リストを選ぶ(ライセンスを確認し、出典を記録する)
  2. そのリストの語のうち、日本語WordNetの見出し語にあるものを機械的に抜き出し、候補にする
  3. 候補を人が1語ずつ確認し、除外するかを決める。既存リストに無くても、確認中に見つけた語は追加する
  4. 加えて、スナップショット用の標準の文章(著作権の切れた作品)を両モード・N=1〜10で変換し、出力された語に不適切な語が無いかを人が確認する
- [ ] リストのファイルが無い、または1語も無い場合、辞書のビルドを失敗させる(リストを入れ忘れたまま公開しないため)
- [ ] ビルドの報告に、リストの語数と、実際に見出し語から除外した数を出す
- [ ] 報告の受付窓口を用意し、「このアプリについて」に載せる。窓口はGitHubのIssue(専用のテンプレートを用意する)とする。リポジトリを公開しない場合は、公開前に別の窓口を決める
- [ ] 報告を受けた語は、確認のうえリストに追加し、辞書のバージョンを上げて反映する。目安として報告から2週間以内に対応する

**語義の選び方**:
- 日本語WordNetの概念は英語WordNetと共通のIDを持つため、英語WordNetの語義頻度(意味タグ付きコーパスでの出現回数)を「よく使われる語義」の指標として使い、最も頻度の高い語義を選ぶ
- 頻度が同じ(または無い)場合は概念IDの小さい方を選ぶ
- アーキテクチャ設計時の検証で、このデータは使えることを確認した。語義が複数ある日本語の名詞のうち、82%で少なくとも1つの語義に頻度があり、76%で一番使われる語義が1つに決まる。残りの約24%は、頻度が同じか無いため概念IDの順で選ばれる(リスク2)

**優先度**: P0(必須)

#### F4. 変換結果の表示

**ユーザーストーリー**:
読者として、どこがどう変わったかを楽しむために、元の文章と変換後の文章を比べて見たい

**受け入れ条件**:
- [ ] 元の文章と変換後の文章を並べて表示する(スマートフォンでは上下に並べる)
- [ ] 置き換えた名詞をハイライトし、元の語と変換後の語の対応が分かる
- [ ] 置き換えた語にカーソルを合わせる(またはタップする)と、元の語が表示される
- [ ] 変換後の文章をワンクリックでクリップボードにコピーできる

**優先度**: P0(必須)

#### F5. N値の変更(S+N)

**ユーザーストーリー**:
創作者として、気に入る結果を探すために、「7つ後ろ」の7を別の数に変えて試したい

**受け入れ条件**:
- [ ] Nを1〜99の整数で指定できる(初期値は7)
- [ ] Nを変えて再変換しても、入力した文章は消えない
- [ ] 1〜99の整数以外が入力された場合は、変換ボタンを押せなくして理由を表示する

**優先度**: P0(必須)。2回目のレビューでP1から変更した。主要画面の操作・ユーザーフロー・KPI(ルールやNを変えて試す)がNの変更を前提にしており、数値の入力欄1つで実装の負担も小さいため

#### F6. 置換経路の表示

**ユーザーストーリー**:
概念版S+7の利用者として、意外な結果の理由を知るために、どの概念をどう辿って置き換わったかを見たい

**受け入れ条件**:
- [ ] 置き換えた語を選ぶと、辿った経路(五十音順なら前後の見出し語、概念版なら通った概念と関係の種類)が表示される
- [ ] 概念には日本語WordNetの語義説明(定義文)を表示する(収録されている場合)

**優先度**: P1(重要)

#### F7. 名詞ごとの置換の除外

**ユーザーストーリー**:
創作者として、結果を作品として仕上げるために、置き換えたくない名詞を個別に外したい

**受け入れ条件**:
- [ ] 変換結果の名詞ごとに「置換しない」を指定でき、指定するとその語は元の語に戻る
- [ ] 指定は再変換(ルールやNの変更)をしても保持される(同じ入力文の間のみ)

**優先度**: P1(重要)

#### F8. 語義の選び直し

**ユーザーストーリー**:
概念版S+7の利用者として、意図した意味で置き換えるために、自動で選ばれた語義を別の語義に変えたい

**受け入れ条件**:
- [ ] 置き換えた語を選ぶと、その名詞が持つ語義の一覧が定義文付きで表示される
- [ ] 別の語義を選ぶと、その語だけが選んだ語義をもとに置き換え直される
- [ ] 選び直した語義は、再変換(Nの変更など)をしても保持される(同じ入力文の間のみ)

**優先度**: P1(重要)

#### F9. 公開Web API

**ユーザーストーリー**:
開発者として、自分のボットや作品にS+7を組み込むために、変換機能をWeb APIで呼び出したい

**受け入れ条件**:
- [ ] Web画面と同じ変換機能(五十音順S+7・概念版S+7)をHTTPのAPIで呼び出せる
- [ ] APIではN値(1〜99、省略時は7)を指定できる(画面のF5と同じくP0)
- [ ] Web画面と同じ入力・同じ設定なら、APIでも同じ結果が返る(画面とAPIは同じ変換処理を使う)
- [ ] リクエストとレスポンスはJSON形式。レスポンスには変換後の文章と、元の文章を「名詞」と「それ以外の文字列」に区切った列を含む。名詞の区切りには「元の語」「変換後の語」「置き換えたかどうかの状態」を含み、区切りの並びが文章中の位置を表す(文字の位置の数値では返さない)
- [ ] P1の機能は、画面への提供と同時にAPIにも追加する。いずれも `/api/v1` のまま行う
  - F6: レスポンスの名詞の区切りに「置換経路」を追加する
  - F7: リクエストに「置き換えない名詞の指定」を追加する。指定された名詞は、状態が「除外した」になる
  - F8: リクエストに「名詞ごとの語義の指定」を追加し、見出し語の語義の一覧を返すエンドポイントを追加する
- [ ] **互換性のある変更の範囲**を決め、API仕様書に明記する
  - 互換性のある変更(`/api/v1` のまま行う): レスポンスへの項目の追加、リクエストへの省略できる項目の追加、エンドポイントの追加
  - 名詞の状態の値は、MVPの時点でP1の値(「除外した」)も含めて全てAPI仕様書に載せる。「除外した」は、リクエストで除外を指定したときだけ返すため、指定しない利用者が受け取ることは無い
  - 利用者のプログラムは、知らない項目を無視する前提とする(API仕様書に明記する)
  - 上記以外(項目の削除・名前の変更・意味の変更、既存のリクエストへの応答で新しい状態の値を返すこと)は互換性の無い変更とし、新しいバージョンで行う
- [ ] 入力の上限はWeb画面と同じ50,000文字
- [ ] 上限内の入力は、JSONでの書き方によらず受け付ける。日本語を `\uXXXX` に変換して送るライブラリ(Pythonの `json.dumps` の既定など)や、絵文字を含む文章でも、50,000文字以内なら本文の大きさを理由に断らない
- [ ] URLにバージョンを含める(例: `/api/v1/...`)。互換性のない変更は新しいバージョンとして提供し、旧バージョンは告知のうえ最低6ヶ月は提供を続ける
- [ ] 利用登録やAPIキーなしで呼び出せる(ログイン不要の方針に合わせる)。乱用は接続元ごとの利用制限で防ぐ
- [ ] 利用制限を超えた場合は、HTTP 429と、次に呼び出せるまでの秒数を返す
- [ ] 入力エラー(文字数超過、不正なN値など)は、原因が分かるエラーコードとメッセージをJSONで返す
- [ ] 本文が1MBを超えるリクエストは、HTTP 413で断る(50,000文字以内の入力はこの上限に達しない)
- [ ] サーバーの起動中(辞書の読み込み中)は、HTTP 503と、再試行までの秒数(`Retry-After`)を返す。利用者のプログラムはその秒数後に再試行する前提とし、API仕様書に明記する。起動中はしばらく使われなかった後の最初のアクセスや、台数が増えるときに起きる
- [ ] 他のWebサイトのブラウザから直接呼び出せる(CORSを許可する)
- [ ] API仕様書(エンドポイント、パラメータ、レスポンス例、利用制限、エラーコード)をWebで公開する
- [ ] API仕様書とレスポンスに、日本語WordNetなど辞書データの出典とライセンス表示を含める
- [ ] 利用規約(禁止事項、無保証、予告なく利用制限を変える可能性があること)をAPI仕様書に掲載する

**優先度**: P0(必須)

### 主要画面と操作フロー

ログインが不要なので、MVPは1画面で完結します。

| 画面 | 目的 | 主な操作 |
|------|------|----------|
| 変換画面 | 文章を変換して結果を見る | 文章入力、ルール選択(五十音順/概念版)、N値変更、変換、コピー |
| このアプリについて | S+7法の説明と辞書のクレジット | 閲覧のみ |
| API仕様書 | 開発者向けのWeb APIの説明(F9) | 閲覧のみ |

**主要ユーザーフロー**:
1. 変換画面を開く → 文章を貼り付ける → ルールを選ぶ → 「変換」 → 結果を確認 → コピー
2. 結果を見る → ルールやNを変える → 再変換 → 結果を比べる

### 将来的な機能(Post-MVP)

#### 他の品詞への拡張(V+7、A+7など)

## 非機能要件

### パフォーマンス
- 変換時間(ボタンを押してから結果表示まで):
  - 10,000文字まで: 2秒以内
  - 50,000文字(上限): 5秒以内
- スマートフォンでの変換時間: 10,000文字まで4秒以内。50,000文字は目標を設けず、計測して記録する(結果の描画が重いため、まず実測値を見て判断する)
- 初回表示: LCP 2.5秒以内(モバイル4G回線相当、Lighthouseで計測)
- **上の目標の測定条件**: サーバーが起動済みの状態(下記のコールドスタートを除く)で、95パーセンタイル値(各20回以上計測)
  - PCの変換時間: PCのChrome最新版、下り10Mbps・往復遅延50ms相当の回線
  - スマートフォンの変換時間: 中くらいの性能のAndroid端末に相当する条件(Lighthouseのモバイル設定と同じく、CPUを4倍遅くし、低速の4G回線に制限したChrome)
- **コールドスタート**: しばらく使われなかった後の最初のアクセスでは、サーバーの起動を待つため、上の目標を満たさなくてよい。その場合も次を守る
  - 画面は起動を待たずに表示し始め、サーバーの準備ができるまで「準備中」であることを表示する
  - 最初の変換結果が出るまで10秒以内
  - 準備中に押された変換は、利用者が押し直さなくても準備ができ次第実行される
  - **測り方**: サーバーが1台も動いていない状態でページを開いた時点から、自動操作で10,000文字の文章を入力してすぐ変換を押し、結果が表示されるまでを測る(利用者が入力にかける時間は含めない)。5回測り、最大値が10秒以内であること。ホスティング先の決定後に実測し、満たさない場合は最小台数を1にすることなどを検討する
- 1秒を超える変換では処理中であることを表示し、二重送信を防ぐ
- 長い結果でもスクロールが滑らかであること(50,000文字の結果でスクロール時にカクつかない)

### ユーザビリティ
- 初めての利用者が説明を読まずに、1分以内に最初の変換を実行できる
- PCとスマートフォン(画面幅360px以上)の両方で全機能を使える

### 信頼性
- 同じ入力・同じ設定・同じ辞書バージョンなら、常に同じ結果を返す(決定性)
- 変換に失敗した場合は、入力した文章を消さずにエラーメッセージを表示する

### セキュリティとプライバシー
- 入力した文章をサーバーに保存しない、ログにも残さない
- 入力文を結果画面に表示する際にHTMLとして解釈しない(XSS対策)
- 変換APIに接続元ごとの利用制限を設け、大量のリクエストでサービスが止まらないようにする。長文に対応するため、回数だけでなく処理した文字数の合計でも制限する(例: 1分あたり30回かつ合計20万文字まで)
- 画面が自動で送る呼び出し(準備中の確認、アクセス解析のイベント)は、変換の回数の制限とは別の枠で数える。画面を普通に使うだけで変換の利用制限に近づかないようにするため(例: 1分あたり120回まで)
- アクセス解析は個人を特定しない匿名の集計だけにし、収集する項目をプライバシーポリシーとしてアプリ内に掲載する
- **接続元IPアドレスの扱い**: アプリは接続元IPアドレスをログに記録しない。利用制限のために、直近1分間の分だけメモリ上で保持し、それより古いものは捨てる。ホスティング先が自動で記録するアクセスログ(IPアドレスやブラウザの情報を含みうる)の内容と保存期間は、ホスティング先の決定時に確認し、プライバシーポリシーに書く

### 運用
- 一般公開するため、低い固定費で運用できる構成にする。使われていないときの費用がほぼかからないホスティング先を選ぶ
- 月額費用の上限は、ホスティング先の決定時に決める(公開前に決め、予算の通知を設定する)。上限を超えそうな場合の対応(台数の上限を下げる、利用制限を厳しくするなど)も同時に決める

### アクセシビリティ
- WCAG 2.2 レベルAA準拠(ハイライトを色だけで示さず、下線などの別の手がかりも付ける)
- キーボードだけで全操作ができる

### ライセンスとクレジット
- 日本語WordNetのライセンス条件に従い、アプリ内に出典とライセンス表示を掲載する
- 読みの付与などに使う他の辞書データも、ライセンスを確認したうえで同様に表示する

## スコープ外

明示的にスコープ外とする項目:
- ユーザー登録・ログイン、変換履歴のサーバー保存
- Web APIのAPIキー発行・有料プラン・利用状況のダッシュボード
- 日本語以外の言語の入力
- 生成AI(LLM)による置換や文章の自然化(置換は辞書とルールだけで決まる)
- 置換後の文法調整(例: 「が」「は」の付け替え。名詞は活用しないため、MVPでは不要と判断)

### アーキテクチャ設計への申し送り

- **辞書データは事前に加工する**: 五十音順リスト、兄弟概念の並び、語義の選択結果などは、ビルド時に日本語WordNetから計算して変換用のデータを作る。実行時は引くだけにして、変換時間の目標(10,000文字まで2秒、50,000文字で5秒)を守る
- **変換はサーバー側で行う**(技術スタックの決定により確定): 辞書データをブラウザに配信しないため、スマートフォンでも初回表示が軽い。Web画面も公開Web API(F9)と同じAPIを使い、変換処理を1か所にまとめる
- **起動の遅さに注意する**: ホスティング先によっては(候補のCloud Runを含む)、使われていないときに停止し、最初のアクセスで辞書の読み込みが発生する。事前加工で辞書を小さくし、起動時間を計測する方針を決める
- **辞書のバージョンを固定する**: 結果の決定性を守るため、日本語WordNetと形態素解析辞書のバージョンを固定し、更新する場合は明示的に行う

## リスク

1. **読みの精度**: 形態素解析辞書で付けた読みが誤っている語(例: 「生物」を「なまもの」と読む)が混ざると、五十音順の並びがずれる。機械的に付けた読みであることを「このアプリについて」で説明する
2. **語義頻度データの偏り**: 検証の結果、語義が複数ある日本語の名詞の約24%では、頻度が同じか無いため、一番使われる語義を頻度で決められない。これらは概念IDの小さい方が選ばれるため、意外な語義になり結果が不自然になることがある。F8(語義の選び直し)で利用者が直せるようにする
3. **兄弟概念の偏り**: 兄弟概念が数個しかない概念では、7つ先が循環して元の語の近くに戻ることがある(例: 兄弟が3つなら7つ先は1つ先と同じ)。結果のつまらなさにつながる場合は、将来の派生ルールで補う
4. **辞書ライセンス**: 日本語WordNetと形態素解析辞書のライセンスが一般公開での利用を認めているか、表示義務は何かを、アーキテクチャ設計の時点で確認する
5. **不適切な語の出力**: 置換先から除外する語のリストは完全ではなく、意図しない語が出力される可能性が残る。「このアプリについて」で説明し、報告を受けてリストを更新する(更新のたびに辞書のバージョンが上がる)
